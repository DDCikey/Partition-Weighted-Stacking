## 1. 架构与安装

WevvMold 采用双代码架构四层链路：

```
┌─────────────────────────────────────────────┐
│ wevvmold（纯 Python 封装层，开发者只接触这层） │  wevvmold/__init__.py
├─────────────────────────────────────────────┤
│ _wevvmold（CPython 原生扩展 .pyd）            │  C ABI 绑定
├─────────────────────────────────────────────┤
│ WevvMoldCore（C++ 核心库 .dll）               │  C ABI 实现 + 控件核心
├─────────────────────────────────────────────┤
│ 平台抽象层 PAL（Win32 + Direct2D）            │  平台相关，上层零泄漏
└─────────────────────────────────────────────┘
```

**运行环境**：Windows 10+，Python 3.x。将 `wevvmold/` 包（含 `_wevvmold.pyd`、`WevvMoldCore.dll`）随应用分发即可 `import wevvmold`。

**核心设计原则（开发者须知）**：
- **能力 API**：核心层不自动绑定任何输入策略（滚轮缩放、快捷键等均由应用层决定）；控件事件由应用经 `dispatch` 注入、经 `poll_*` 轮询取出。
- **时钟无壁钟**：核心层不读取系统时间——动画/特效时钟由宿主逐帧喂入 `tick(dt)` / `update(dt_ms)`，行为完全确定。
- **生命周期**：所有持有句柄的类（Window/Control/Image/Icon/Canvas/Chart/DataGrid/FxEngine）使用 `close()` 释放；`close()` 幂等，关闭后调用方法抛 `RuntimeError`。

## 2. 快速开始

```python
from wevvmold import WevvMoldWindow, WevvMoldControl, color

win = WevvMoldWindow(title="Hello", width=480, height=320, left=100, top=100)

def on_render(rc):                       # 渲染回调：每帧绘制窗口内容
    rc.fill_rect(0, 0, 480, 320, color(30, 34, 46))
    rc.draw_text("你好，织铸！", 20, 40, 460, 80, 22, color(230, 236, 246))

def on_event(ev):                        # 事件回调：ev 是 dict
    if ev["type"] == win.EVENT["CLOSE_REQUESTED"]:
        win.request_close()

win.on_render = on_render
win.on_event = on_event
win.show()
win.run()                                # 阻塞式消息循环；退出后返回 exit_code
win.close()
```

**事件模型**：`win.on_event = 函数`。事件为 dict，字段固定：
`type / x / y / width / height / button / wheel_delta / key_code / repeat_count / ctrl / shift / alt / timer_id / char_code`。
事件类型常量见 `WevvMoldWindow.EVENT`（同 `WEVVMOLD_EVENT`）。

**渲染模型**：`win.on_render = 函数(rc)`。`rc` 是当前帧渲染上下文，仅在回调期内有效；窗口失效区域变化时由框架重绘。主动请求重绘用 `win.request_redraw()`。

**帧驱动**：`win.start_timer(timer_id, interval_ms)` 启动帧定时器，事件流中以 `TIMER_TICK` 类型到达（tick 由高精度节拍线程投递，间隔稳定，可直接驱动动画/特效时钟）。`win.stop_timer(timer_id)` 停止。

## 3. 窗口：WevvMoldWindow

无边框自绘窗口：DWM 自定义框架、标题栏三控制按钮（hover 动画）、拖拽/缩放/最大化/最小化/贴边、DPI 感知、毛玻璃二级窗口。

```python
WevvMoldWindow(title="", width=320, height=240, left=0, top=0)
```

| 方法 | 说明 |
|---|---|
| `show()` / `hide()` | 显示 / 隐藏窗口 |
| `set_title(title)` | 设置标题栏文本 |
| `run()` | 进入消息循环（阻塞），返回 exit_code |
| `request_close()` | 请求关闭（发出 `CLOSE_REQUESTED` 事件后退出循环） |
| `close()` | 销毁窗口并释放（幂等） |
| `should_quit()` | 消息循环是否应退出 |
| `start_timer(timer_id, interval_ms)` / `stop_timer(timer_id)` | 帧定时器（节拍线程投递，稳定 60fps 可用） |
| `request_redraw()` | 请求重绘 |
| `set_frosted_host(host_window)` | 毛玻璃背景源（宿主窗口） |
| `set_frosted_glass(blur, brightness=1.0, tint=None)` | 毛玻璃三参数（模糊半径 / 亮度 / RGBA 染色） |
| `set_frosted_mode(realtime)` | 模糊模式：True=实时（动态跟随）/ False=静态（一次性捕获，省电） |

**实例属性**：`on_event`（事件回调）、`on_render`（渲染回调）——直接赋值函数或 None。
**类属性**：`EVENT`（事件类型常量 dict）。

毛玻璃二级窗口最小示例：

```python
main = WevvMoldWindow(title="主窗口", width=600, height=400)
main.show()
panel = WevvMoldWindow(title="毛玻璃面板", width=280, height=180, left=200, top=150)
panel.set_frosted_host(main)             # 以主窗口内容为模糊背景
panel.set_frosted_glass(8.0, 1.06, (0.5, 0.7, 0.9, 0.1))
panel.set_frosted_mode(True)             # 实时模式
panel.show()
```

## 4. 渲染：WevvMoldRenderContext 与 color

`on_render(rc)` 回调期内可用的绘制命令（坐标为窗口客户区逻辑坐标）：

| 方法 | 说明 |
|---|---|
| `fill_rect(left, top, right, bottom, color)` | 实心矩形 |
| `fill_ellipse(cx, cy, rx, ry, color)` | 实心椭圆 |
| `fill_polygon(points, color)` | 实心多边形，`points=[(x,y),...]` |
| `draw_text(text, left, top, right, bottom, size, color, valign=0, halign=0)` | 区域内文本；`valign/halign`: 0=左/上 1=中 2=右/下 |
| `measure_text(text, size) -> float` | 20261006：文本度量——返回指定字号下文本实际渲染宽度（逻辑像素，不含尾随空白，与 `draw_text` 绘制的视觉右缘一致；空串返回 0.0；仅 on_render 回调内可用） |
| `render_control(control, dx=0.0, dy=0.0)` | 将控件（含容器族）自绘到窗口，`(dx,dy)` 为原点偏移 |
| `upload_bitmap(width, height, pixels) -> token` | 上传 RGBA 像素位图（pixels: `bytearray`，每像素 4 字节） |
| `draw_bitmap(token, src_rect, dst_rect, opacity=1.0, interpolation=1)` | 绘制位图（`interpolation`: 0=最近邻 1=线性；`IMAGE_INTERPOLATION`） |
| `destroy_bitmap(token)` | 释放位图 token |
| `draw_icon(icon, x, y, size)` | 绘制逻辑图标（自动选 DPI 档位） |

**color 工具函数**：`color(r, g, b, a=255)` — 0..255 整数转 `(r,g,b,a)` 0..1 浮点元组。所有绘制命令的 `color` 参数均接受 0..1 浮点元组。

### 6.2 事件注入与轮询（能力 API 模型）

应用将输入事件喂给控件、再轮询取回语义事件：

```python
c.dispatch(kind, x=0.0, y=0.0, key_code=0, char_code=0)      # kind: CONTROL_EVENT
c.dispatch_ex(..., modifiers=0)                              # 位标志 1=Ctrl 2=Shift 4=Alt
c.dispatch_wheel(x, y, wheel_delta, ctrl=False, shift=False, alt=False)

c.poll_clicked()            # 点击是否发生（自上次轮询后）
c.poll_value_changed()      # 数值变化（滑块/微调/进度）
c.poll_text_changed()       # 文本变化（输入框/文本域，逐键）
c.poll_selection_changed()  # 选择变化（列表/下拉）
```

`CONTROL_EVENT`：MOVE / PRESS / RELEASE / LEAVE / KEY_DOWN / KEY_UP / CHAR / WHEEL / FOCUS_IN / FOCUS_OUT。
`CONTROL_POLL`：CLICKED / VALUE_CHANGED / TEXT_CHANGED / SELECTION_CHANGED（`poll(which)` 的 which 取值）。

## 17. 使用要点与常见陷阱（20261005）

以下条目全部来自综合展示程序（showcase）开发与目检修复中的真实踩坑，开发者接入前务必阅读：

### 17.1 控件缺省矩形为零，render_control 前必须 set_rect
控件创建后缺省矩形为 `(0, 0, 0, 0)`。`render_control` 按 rect 的宽高做内部布局，零矩形控件**什么都不画**（图表、统计表、画布尤其明显——整页空白且无报错）。凡经 `rc.render_control(ctrl, ...)` 呈现的控件，先 `ctrl.set_rect(0, 0, w, h)`。

### 17.2 render_control 的坐标语义
`rc.render_control(ctrl, dx, dy)` 把控件画在**窗口坐标 (dx, dy)**；rect 数值只影响控件内部布局尺寸，不影响呈现位置。同一位置后画的覆盖先画的。

### 17.3 带平移钩子的路径必须以局部 (0,0) 自绘
`WevvMoldFxEngine.apply_pre_render(win, ctrl, x, y)` 已把坐标系平移到 (x, y)，随后必须 `rc.render_control(ctrl, 0, 0)`；再传 (x, y) 会双重平移，把控件画到屏幕外。

### 17.4 非拥有型注册 API 的 Python 侧保活
`floating_set_content`、`popup_open` 的菜单面板、`fx.attach_*` 系列为**非拥有指针**：原生侧只存裸指针。Python 包装对象被垃圾回收时会触发 `__del__ → destroy_control` 销毁原生控件，导致悬垂指针（表现为渲染出无关控件内容、间歇性原生崩溃）。被注册的内容控件必须保活到宿主窗口关闭（如存入长寿命状态容器）。`add_child` 子控件由容器拥有，无此要求。

### 17.5 容器族必须显式初始化
- `TAB` 必须先 `tab_set_active(0)`（缺省活动页签 -1，内容区不渲染）；`STACK`/`DOCK` 同理须设活动页。
- `SPLITTER` 必须设 `splitter_set_split_width(...)` / `splitter_set_split_pos(...)`（缺省分栏宽 0，布局错乱）。
- 子内容用**局部坐标**：STACK 内容避开顶部切换条（高 26）、TAB 避开页签条、DOCK 内容区从停靠栏宽 90 起。

### 17.6 事件只到达宿主，命中转发是宿主的责任
指针/滚轮事件只出现在 `win.on_event`。宿主需自行做矩形命中并把事件转给控件：`ctrl.dispatch(kind, x=局部x, y=局部y)`（kind 为 `"PRESS"/"RELEASE"/"MOVE"`），滚轮用 `ctrl.dispatch_wheel(...)`；一次性结果（点击/值变化/文本变化/选择变化）用 `poll_*` 轮询。容器控件可整体 dispatch（内部自带命中减偏移转发）。

### 17.7 图表数据语义
`set_series_points` 接受**扁平数值列表** `[x0, y0, x1, y1, ...]`；K 线为 4 浮点一组（o/h/l/c）无索引；热力图每序列一行；饼/环用分类数据。

### 17.8 复合控件留意缺省尺寸
`WIZARD` 按约 420×260 设计内部布局（标题/步骤指示/内容/底部按钮），容器给的矩形过矮会导致内容与按钮重叠。
